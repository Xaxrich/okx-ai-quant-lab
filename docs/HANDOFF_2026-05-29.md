## Main Commands

### Current best manual sequence

This is more reliable than the full runner while OKX/CoinGlass APIs are bursty:

```bash
npm run intelligence:accumulation:okx-scan -- --limit=30 --min-volume-usd=2000000 --min-oi-usd=1000000 --target-cap=small-mid
npm run intelligence:accumulation:chain-candidates -- --limit=100 --min-accumulation=15 --min-execution=40 --max-risk=40 --write-chain-candidates
npm run validation:chain-gate -- --input=data/altcoin/intelligence/validation/accumulation_chain_candidates_latest.csv --min-opportunity=15 --min-tradability=40 --max-fragility=40
```

Then run CEX flow for the current candidates:

```bash
npm run intelligence:onchain:cex-flow -- --tokens=CHZ,ENA,OP --pages=80 --windows=1,4,24 --target-window-hours=24
npm run intelligence:onchain:readiness
npm run intelligence:onchain:directional
npm run intelligence:onchain:qualified-subset
npm run intelligence:accumulation:okx-scan -- --limit=30 --min-volume-usd=2000000 --min-oi-usd=1000000 --target-cap=small-mid
```

Do not run readiness and directional in parallel. `directional` reads `scan_readiness_latest.csv`, so parallel execution can race and read stale readiness data.

If Moralis hits pagination/auth limits or you need to compare explorer-only transfer history:

```bash
npm run intelligence:onchain:cex-flow -- --tokens=CHZ --source=explorer --pages=30 --windows=1,4,24 --target-window-hours=24
```

Use explorer-only output as a cross-check, not as a stronger source by default. Explorer row limits and lower label coverage can change the interpretation.

### Full cycle runner

The runner was updated so onchain scans are built from the current accumulation candidates rather than an older point-in-time label file:

```bash
npm run intelligence:accumulation:cycle -- --limit=30 --bootstrap-limit=60 --coinglass-limit=20 --target-cap=small-mid --chain-limit=6 --cex-flow-pages=60 --cex-flow-target-window=24
```

Known issue: the full runner can still fail before completion if OKX returns an empty public universe or if `chain-gate` returns exit code 2 for zero ready candidates. The manual sequence above is the safer takeover path.

Examples from latest repair queue:

- `XPL`, `APT`, `FIL`, `PUMP`, `TRUMP`, `ORDI`, `SEI`, `JTO`, `GRASS`, and others often show `missing_contract_address` or an unsupported non-EVM chain.

Next useful work: improve CoinGecko/registry contract mapping before spending more onchain budget.

4. Latest-output audit is expected to fail after manual recovery unless a full cycle completes.

Current failure reason:

- `cycle covers final scan` fails because the cycle report was generated before the manually recovered final scan.

This is not a code compile failure. It means `reports/altcoin/intelligence/cycles/accumulation_cycle_latest.md` does not describe the latest manual final scan.

5. CoinGlass can hit rate limits and preserve previous latest output.

Use `--coinglass-limit=20` or smaller. Avoid using `--bootstrap-limit` directly for CoinGlass.

## Recommended Next Steps

1. Fix the full cycle runner to handle zero ready candidates gracefully.

`chain_scan_gate.ts` intentionally sets `process.exitCode = 2` when `ready.length === 0`. For an operator runner, that may be too strict. Either catch exit code 2 in `accumulation_cycle_runner.ts` and write a completed no-candidate cycle report, or add an explicit `--allow-empty` mode to `chain_scan_gate.ts`.

2. Improve metadata repair for small/mid OKX swaps.

Start with tokens in `data/altcoin/intelligence/validation/data_repair_queue_latest.csv`.

The highest-impact repair is mapping OKX symbols to:

- `coingecko_id`
- `asset_platform_id`
- `primary_contract`
- normalized EVM chain

3. Add a safer OKX universe fetch retry.

One cycle returned `Universe selected: 0` immediately after a successful 60-row OKX scan. Add a retry/backoff guard in `okx_accumulation_scan.ts` and `coinglass_okx_universe_features.ts` so a transient empty public response does not overwrite latest files.

4. Make latest-output audit snapshot-aware across onchain artifacts.

Current audit checks freshness and stage presence, but does not prove that onchain outputs match the current final candidate set. Add candidate token-set checks between:

- `accumulation_chain_candidates_latest.csv`
- `chain_scan_candidates_latest.csv`
- `cex_flow_window_scan_latest.csv`
- `scan_readiness_latest.csv`
- `directional_chain_scan_latest.csv`
- `okx_accumulation_features_latest.csv`

5. Continue scanning beyond CHZ.
